# 发布文案：让成片可以直接交给运营

制作完一条短视频，默认一起交付 UTF-8 的 `发布文案.txt`。它是标题、平台正文、相关入口和必要交接信息的可复制版本，不是逐字稿、长篇伴读或等待运营再写的提纲。只补文案时也可单独使用本文件：读最终成片的精校字幕、现有封标和本期链接，不重新剪辑。

## 先认准要发的那一条

以最终成片及其对应字幕为依据。原始长稿里被剪掉的内容，不能写成这条短片的卖点；有上、下集时分别看每条兑现了什么。保留已定稿的标题和用户改过的正文，只修实际不一致的地方。

最少需要知道：

- 哪个文件是本次发布版，以及是否有独立分集、完整母版；
- 这条片的具体观点、例子或情境，以及已选的标题和封面文字；
- 面向哪些平台、哪个账号与受众；只交付草稿还是也执行发布；
- 本期提到的课程、访谈、商品、社区帖等入口和可核对来源。

已有字幕和上下文足够时直接写。账号、商品挂载或排期尚未核实时，仍完成不依赖它们的正文；把缺口留在运营说明里，不把猜测写进可复制正文。只给了摘要时说明依据有限，不声称已经核对整片。

## 写观众能理解的具体内容

先找本期最值得看的一个关系：遇到了什么问题，片中怎样判断，为什么这样判断。第一句直接进入这个情境或观点，后面只补让它成立的必要例子、理由或使用条件。短小的生活片可以只有一句；复杂的技术片可能需要几段。没有统一字数，也不要求每条都有问题、反转、教程或 CTA。

例如，材料说的是“老板不逐行重写员工代码；管理 AI 也要设目标、做检查、验收结果”，文案应让这层关系可见。写成“AI 时代，认知决定上限，拥抱未来”就把真正的内容抹掉了。可以写“AI 任务多起来，难点会从逐步操作变成目标、检查和验收”，再用片中那个具体场景展开；不要从中推导“完全不用审核”。

- **标题和正文分工。** 标题让人认出为什么值得看；正文补出情境、内容和入口。不要把封面几个大字机械复制成整段介绍。已选标题有明确问题时，正文可以给出部分答案，不需要再制造一层悬念。
- **保留原来的声音。** 本人账号可以用“我”；采访片要分清是谁说的、谁做的。切片号的运营说明不能混成创作者自述，未经确认也不能写“我们团队亲测”。
- **保留改变判断的条件。** 400 个工作区不等于 400 个任务一直并行；个案不等于所有人；演示不等于已经上线。把必要限定写进相邻句子，不用堆免责声明掩盖主要内容。
- **少写空泛评价。** “干货满满”“颠覆认知”“建议收藏”不能代替观点、机制或实例；不要替创作者宣布“独家”“全网首次”“必爆”。
- **忠于有意的表达。** 有意留白、停顿、幽默和悬念按本期意图保留。不要为了“补齐内容”把设计好的包袱在正文里解释掉，也不要把真正的口误包装成巧思。

无需为短发布文案强行调用长文写作流程。只有另行要求完整文章或社区帖时，再转入相应写作 Skill。

## 链接跟着内容走

不是每条都挂全部主页。选观众看完这条最可能需要的下一步，并说明点开能看什么；完整访谈、相关课程、引用帖子和商品各有用途，不要用一串裸链接代替说明。

核对链接实际页面、标题和访问条件。公开落地页可以访问，不代表里面所有课程、回放都免费；App 可以免费下载，不代表所有内容免费。价格、活动时间、名额、免费次数、会员权益和商品库存是易变信息，需要按本次来源确认；无必要时不写这些数字。

一般的配对关系：

| 成片在说什么 | 有用的入口 | 不应自动附加 |
| --- | --- | --- |
| 某次访谈里的具体方法 | 对应完整访谈、伴读或时间点 | 同频道任意一条热门视频 |
| 课程能力、作品或练习 | 对应课程页／本次实际展示的页面 | 无法证实的学习效果、免费承诺 |
| 社区讨论、案例、Skill | 原帖或可找到该帖的社区／App 路径 | “已在评论区置顶”，但实际没有 |
| 书或商品 | 已核对的版本与读者购买入口 | 商家后台链接、旧版权益 |
| 身上穿的 swag | 核对过的同款商品或可用原生商品 tag | 所有周边、相似但不同的款式 |
| 个人生活、随想、短笑话 | 可以没有外链和 CTA | 硬接课程销售 |

立正的公开入口只是选材起点，见 [个人偏好](creator-profile.md)；不要把这些账号或链接复制给其他创作者。商品卡的实际挂载另按 [商品交付](product-recommendations.md) 核验，写了商品名不等于已经挂好。

## 按实际发布平台交付

| 平台／用途 | 文案如何准备 |
| --- | --- |
| YouTube | 分开给标题和简介。简介按语境放完整 URL 与用途；本期适用的 Related Video 是单独的设置，不因简介里有链接就算设置完成。 |
| Instagram | 给一段完整的 caption，第一句进入具体情境。不要假设 caption 中 URL 可以点击；可用域名帮助辨认。只有核对当前个人简介确有对应入口后，才写“个人简介里有链接”。 |
| 小红书／抖音等 | 仅在本批要求或运营明确要该平台文案时准备相应块。标题和正文分开；按当前平台能力处理入口、活动话题、商品组件与披露。域名的显示格式不代表平台允许导流，更不能用变形链接规避限制。 |
| Google Drive | 归档成片、字幕、封面及同版 `发布文案.txt`；它不是另一个公开发帖渠道。 |

语言、标题长度和正文限制按目标账号的实际编辑器核对，不把某次上限写死成永久规则。没有必要为了“国际平台”自动把中文口播文案翻成英文。

话题只保留相关的主题、产品或人物。数量服从内容和当前平台，不凑固定个数；活动话题要核对本期活动。`#名字`、正文提及、原生 `@账号`、商品 tag 是不同功能，不能互相冒充。缺少精确账号时不要随手 tag 同名用户。

## 文件格式与运营交接

使用 [模板](../templates/发布文案模板.txt) 的块结构，删掉不适用的块，填成最终文本。模板是整理方式，不是固定句式。

- 标题、正文、标签和面向读者的链接在相应平台块里一起给全，复制该块正文就能发，不让运营从几份文件中拼装。
- `【运营说明｜不要复制到正文】` 单独写：成片文件、平台对应账号、是否本批要发、已发布／已排期／待核验的状态，以及分集或母版选择。不要把内部路径、排错信息和“待确认”混进正文。
- 平台相同文案可共用，但必须说清哪些平台用哪一块。只有一个目标时只留一套，不强制三平台变体。
- 缺少发布状态时写“未核验”，不能写“未发过”；文案写好了只能标作文案完成，不能标作已发布。
- 一期只有一个权威文件。已有 `.md` 可沿用，若运营需要 `.txt`，从同一份最终内容导出，不保留两份各自修改的真相。修改视频或标题后复核文案；线上成功后把实际文案和回执同步回来。
- 本期有上下集时，给每个发布单元独立的文案和对应成片。完整母版默认作归档用途，只有本次明确要发才列入发布单元；不能让运营在几个“正式稿”中猜一个。

写进运营说明的账号是本期已确认的账号。主号、切片号、会客厅不能互相推导；同一条内容能在 YouTube 主号发，不等于自动授权在其他账号重复发。

## 完成检查

把最终成片、封标和 `发布文案.txt` 放在一起读一遍：观众会期待什么，视频是否兑现，下一步是否真的能到达？核对人名、数字、归因、易变权益和链接；正文里不留模板变量、编辑备注、未查证的账号或状态。确认运营不用再想标题、不用重写正文，也不用猜哪个 MP4。

只补文案时，到这个状态就完成，不重新渲染、不自动发帖。要求上传或排期时，再读 [分发与交接](publishing.md)，执行已获授权的范围并核验实际结果。
