# 发布文案：发布的人复制就能用

成片做完，一起交付 UTF-8 的 `发布文案.txt`。它是各平台标题、正文、相关入口和话题的可复制版本，不是逐字稿、长篇伴读，也不是等发布的人再去改写的提纲。只补文案时也可以单独用这份文件：读最终成片的精校字幕、已有封标和本期链接，不重新剪辑。

## 先认准是哪一条

以最终成片和对应的字幕为准。原始长稿里被剪掉的内容，不能写成这条成片的卖点。有上下集时分别看每条兑现了什么。已经定稿的标题和用户改过的正文保留，只修实际不一致的地方。

最少需要知道：

- 哪个文件是这次的成片，是否还有分集或完整母版；
- 这条片具体讲了什么观点、例子或情境，标题和封面上写了什么；
- 本期提到的课程、访谈、商品、社区帖等入口，以及可以核对的来源。

字幕和上下文够用时直接写。某个链接或权益一时核实不了，照样写完不依赖它的正文，把缺口记在文件开头的说明里，不把猜测写进可复制的正文。只拿到摘要时，说明依据有限，不声称看过整片。

## 写观众能理解的具体内容

先找本期最值得看的一个关系：遇到了什么问题，片中怎样判断，为什么这样判断。第一句直接进入这个情境或观点，后面只补让它成立的必要例子、理由或使用条件。短小的生活片可以只有一句，复杂的技术片可能要几段。没有统一字数，也不要求每条都有问题、反转、教程或引导语。

例如，材料说的是“老板不逐行重写员工代码；管理 AI 也要设目标、做检查、验收结果”，文案就应该让这层关系可见。写成“AI 时代，认知决定上限，拥抱未来”，就把真正的内容抹掉了。可以写“AI 任务多起来，难点会从逐步操作变成目标、检查和验收”，再用片中那个具体场景展开；不要从中推出“完全不用审核”。

- **标题和正文分工。** 标题让人认出为什么值得看，正文补出情境、内容和入口。不要把封面上的几个大字机械复制成整段介绍。标题已经提了一个明确的问题时，正文可以给出部分答案，不需要再制造一层悬念。
- **保留原来的声音。** 本人账号可以用“我”。采访片要分清是谁说的、谁做的。
- **保留改变判断的条件。** 400 个工作区不等于 400 个任务一直并行；个案不等于所有人；演示不等于已经上线。必要的限定写在相邻的句子里，不用堆免责声明盖住主要内容。
- **少写空泛评价。** “干货满满”“颠覆认知”“建议收藏”代替不了观点、机制或实例。不替创作者宣布“独家”“全网首次”“必爆”。
- **忠于有意的表达。** 有意的留白、停顿、幽默和悬念按本期意图保留。不要为了“补齐内容”在正文里把设计好的包袱解释掉，也不要把真正的口误包装成巧思。

短的发布文案不需要走长文写作流程。另外要写完整文章或社区帖时，再用相应的写作 skill。

## 链接跟着内容走

不是每条都挂全部主页。选观众看完这条最可能需要的下一步，并说明点开能看到什么。完整访谈、相关课程、引用的帖子和商品各有用途，不要用一串裸链接代替说明。

核对链接的实际页面、标题和访问条件。公开落地页能打开，不代表里面所有课程、回放都免费；App 可以免费下载，不代表所有内容免费。价格、活动时间、名额、免费次数、会员权益和库存是易变信息，按本次来源确认，没必要时不写这些数字。

常见的对应关系：

| 成片在说什么 | 有用的入口 | 不应自动附加 |
| --- | --- | --- |
| 某次访谈里的具体方法 | 对应的完整访谈、伴读或时间点 | 同频道任意一条热门视频 |
| 课程能力、作品或练习 | 对应课程页，或本次实际展示的页面 | 无法证实的学习效果、免费承诺 |
| 社区讨论、案例、Skill | 原帖，或能找到该帖的社区／App 路径 | “已在评论区置顶”，但实际没有 |
| 书或商品 | 核对过的版本和读者的购买入口 | 商家后台链接、旧版权益 |
| 身上穿的 swag | 核对过的同款商品 | 所有周边、相似但不同的款式 |
| 个人生活、随想、短笑话 | 可以没有外链和引导语 | 硬接课程销售 |

立正的公开入口只是选材的起点，见 [个人偏好](creator-profile.md)；不要把这些链接复制给其他创作者。商品怎么准备，见 [商品推荐](product-recommendations.md)；写了商品名，不等于商品卡已经挂好。

## 每个主要平台一块

没说具体发哪些平台时，按全平台准备：YouTube、Instagram、小红书、抖音、视频号。用户指定了平台，就只写那几块。

| 平台 | 文案怎么准备 |
| --- | --- |
| YouTube | 标题和简介分开。简介里按语境放完整网址和它的用途；适合关联某条视频时，在设置提示里写明是哪一条。 |
| Instagram | 一段完整的 caption，第一句进入具体情境。不要假设 caption 里的网址能点开，可以写域名帮人辨认。 |
| 小红书 | 标题和正文分开，标题短，正文第一段就进入这期的情境或判断。 |
| 抖音、视频号 | 标题（或描述的第一句）和正文。两个平台可以共用一块，但要写明适用于哪两个。 |

各平台对标题长度、正文长度、外链和话题的限制会变，以写作当时的实际编辑器为准，不把某一次的上限写死。域名的写法不代表平台允许导流，不要用变形的链接绕过限制。没有必要把中文口播的文案自动翻成英文。

话题只保留和主题、产品、人物相关的，数量服从内容和平台，不凑固定个数。`#名字`、正文里的提及、平台的 `@账号`、商品标签是不同的功能，不能互相冒充；不知道准确账号时，不要随手 `@` 同名用户。

## 文件格式

用 [模板](../templates/发布文案模板.txt) 的块结构，删掉不适用的块，填成最终文本。模板是整理方式，不是固定句式。

- 每个平台块里的标题、正文、话题和面向读者的链接一次给全，复制那一块就能发，不需要从几份文件里拼。
- 文件开头的 `【对应成片｜不要复制到正文】` 写清：这份文案对应哪个成片文件、分集或母版的选择，以及确实没核实的链接或权益。内部路径、排错信息和“待确认”不能混进正文。
- `【平台设置提示｜不要复制到正文】` 只写发布时需要在平台上另外设置的东西，例如关联视频、商品卡、活动话题，并注明哪些已经核对、哪些还没有。
- 一期只有一个权威文件。已经有 `.md` 可以沿用，需要 `.txt` 时从同一份最终内容导出，不保留两份各自修改的版本。改了视频或标题以后，复核文案。
- 有上下集时，每个发布单元各有自己的文案和对应成片。完整母版默认只归档，只有用户明确要发时才单独写一份。

## 完成检查

把最终成片、封标和 `发布文案.txt` 放在一起读一遍：观众会期待什么，视频是否兑现，下一步能不能真的到达？核对人名、数字、归属、易变的权益和链接。正文里不留模板变量、编辑备注或没查证的账号。确认发布的人不用再想标题、不用重写正文，也不用猜是哪个 MP4。

只补文案时，到这一步就完成了，不重新渲染，也不发帖。
