# 分发与运营交接

只生成文案时读 [publication-copy.md](publication-copy.md) 即可。上传、排期、补传、对账或交给运营时才读本文件。平台入口会变化，以本次实际界面、官方接口和读回结果为准。

## 一个发布单元，一份准确的记录

用已有项目清单保存：准确的成片／字幕／封面路径和哈希、最终标题及各平台正文、平台与账号 ID、目标目录及受众、可见性、排期和时区、适用的产品卡／关联视频／声明、批准证据，以及远端 ID 和结果。不要求为了这些字段另造网站或拆十几个文件。

`发布文案.txt` 是给人的可复制交付物，执行清单是工具使用的同一版内容；不要维护两份会互相漂移的文案。改正文、换成片或改排期后，重新核对对应版本和授权范围。

## 授权落在执行边界

公开仓库、历史案例和创作者账号配置都不能授权发布。遵守当前用户与工作区的授权规则：实际外部上传、公开编辑或排期前，展示准确文件和文案、目的地、受众与设置，并取得覆盖这些内容的明确批准；已经批准且未变化的同一动作不重复询问。实质变更重新批准。

本地剪辑、写文案、生成发布清单和只读核对先做完，不因为发布待批准就留下半成品。新自动化默认 dry-run，在执行边界验证批准与当前 manifest 匹配；账号绑定和 `live=true` 本身不是任意新内容的发布权。原来的某次长期授权不能覆盖更新的用户指令。

## 排期先合并同平台的真实队列

按本期指定的节奏寻找最近的未来空位，不为了沿用旧表把新视频推到很远。创作者若沿用西雅图每天 17:00，使用 `America/Los_Angeles` 计算当地时间，再转换平台时间戳；夏令时不能写死 UTC 偏移。YouTube 和 IG 分别检查，队尾日期不能互相套用。

**同平台也可能有多个排期入口。** 一次真实核对中，Instagram 原生排期页显示 10 月 16–27 日为空，但 Meta Business Suite 里已经排了连续 12 条。这个案例不证明平台永远这样显示，而是要求：若该账号用过两种入口，核对 IG 原生排期与 Meta Business Suite，再加上自己 bot 尚未提交平台的队列，按远端内容 ID 去重后选空位。看不到另一入口时明确“队列未完整核验”，不要直接插入或顺延。

区分“平台原生排期”和“本地 bot 到点才上传”。后者不能写成已在 IG 排期成功。重试前先按任务记录和远端 ID 查询结果；不确定上次上传是否成功时先对账，不立刻再发一遍。用户要求插队或顺延时准备新旧日期清单，不能覆盖既有内容。

## 平台结果怎么验

- **YouTube：** 按 [youtube-shorts.md](youtube-shorts.md) 核对频道、成片、字幕、标题简介、可见性／排期、关联视频和实际封面状态。草稿、旧版和母版不因为文件名相似就进入发布队列。
- **Instagram：** 核对准确账号、Reel 与封面、完整 caption、原生 tag 和排期时区；分别读回原生／Meta 的结果。未要求时不跨发 Facebook。caption 里的商品名不算商品 tag，第一帧有封面不算平台选封面成功。
- **Google Drive：** 使用已确认的主目录和原有共享范围。本批可建一个交付目录，里面按期分文件夹；维护已有布局时不批量重命名。上传成片、字幕、封面、发布文案与简短清单，不默认上传私人原片、全套工程或新建另一个私有库。按文件 ID 核验大小、校验值或下载内容；只比较同一算法的校验值。
- **小红书及其他平台：** 只执行本期范围内的目标；核对对应账号、适用文案、封面比例、商品组件和审核状态。提交审核不等于公开可见。

修订已归档文件时识别准确 file ID 并用平台支持的版本更新方式；不要先删除已分享的文件。平台不能替换视频本体时，另传或删除旧帖会改变链接与发布记录，按明确范围处理，不把改标题当成已经替换视频。

## 给剪辑／运营同学的批次清单

几条视频一起交付时，一个简短清单足够：每行是一条独立发布单元，列出主题、成片文件、对应文案、目标账号、已发／已排期／待处理状态和远端链接。清楚注明“共几条可发布短片，另有几份仅归档母版”；原片数、项目数、MP4 数不等于应发布条数。

排期写当地日期、时间和时区。状态来自实际读回，没查就标未核验；不让接手者把已发布内容再发一次。用户没要求时无需额外 PDF、HTML 或剪辑对照网站。
